# Проверка обработки видео аккаунтов

Измерено 16.11.2026 локально на Windows x64, FFmpeg/ffprobe
`9.0.2-essentials_build-www.gyan.dev`, один поток кодировщика. Использована
сборка Gyan, указанная на [странице загрузок FFmpeg](https://ffmpeg.org/download.html);
SHA-256 ZIP проверен по опубликованному файлу контрольной суммы. В репозиторий
бинарники не добавляются; production-образ получает FFmpeg из Debian packages.

## Что именно измерялось

Синтетический движущийся `testsrc2`, исходник 1280×720 или 720×1280, 10 fps,
H.264 CRF 18. Это **не съёмка игры и не запись с iPhone**. Получение тестового
исходника не включено во время обработки. Процессор переводит его в MP4,
H.264/yuv420p до 854×480 или 480×854, с `moov` перед `mdat` для progressive
playback. Время обработки включает probe, кодирование и проверку результата.

| Длительность / исходник | Исходник, МБ | MP4 480p, МБ | Уменьшение | Обработка, с |
| --- | ---: | ---: | ---: | ---: |
| 30 с, горизонтальный MP4 | 14.630704 | 1.610588 | 89.0% | 2.336 |
| 60 с, вертикальный MOV | 31.555861 | 3.594226 | 88.6% | 4.555 |
| 120 с, горизонтальный MP4 | 58.566539 | 6.431479 | 89.0% | 9.031 |
| 180 с, вертикальный MOV | 94.741283 | 10.762297 | 88.6% | 14.689 |

Здесь МБ = 1 000 000 байт. На Railway CPU, нагрузка и время будут другими.
Эти результаты нельзя выдавать за скорость обработки произвольной записи игры
или обещание пользователю закончить загрузку за фиксированное время.

## Передача до и после добавления очереди

Одинаковые исходные байты дважды переданы через тот же HTTP ASGI transport,
авторизацию и временную локальную файловую систему: сначала по совместимому
контрольному пути без обработки, затем с постановкой в очередь. Это **не
мобильная сеть**, не Telegram WebView и не сравнение двух production-релизов.

| Исходник | Контрольный PUT, с | PUT с очередью, с |
| --- | ---: | ---: |
| 30 с | 0.0329 | 0.0314 |
| 60 с | 0.1010 | 0.0710 |
| 120 с | 0.1660 | 0.1333 |
| 180 с | 0.2309 | 0.2146 |

Разница этих малых локальных величин подвержена кэшам и порядку прогонов; она
**не доказывает ускорение сети**. Серверная компрессия не уменьшает первую
передачу исходника. Ранний upload позволяет делать её параллельно заполнению
полей; уменьшенный результат экономит хранилище и последующий просмотр.
Измерений реальной мобильной сети и физических iPhone/Android нет.

Исходный лимит upload остаётся серверным. Для теста 180 секунд используется
94.7 МБ, укладывающихся в текущие 100 МиБ. Более тяжёлые исходники корректно
отклоняются; не обещаем приём любого 3-минутного файла независимо от его размера.

## Проверки

Локально: 10 passed в `tests/test_account_video_processing.py` за 43.34 с.
Повторная проверка после fencing worker-claim и изменений очистки: 6 passed,
2 skipped (PostgreSQL не настроен), 4 deselected (длинные замеры не повторялись)
за 2.53 с; Ruff новых тестов проходит.
Проверены настоящий H.264/AAC, пропорции/ориентация, faststart, remux небольшого
совместимого ролика без upscale, повреждённый контейнер, лимит длительности,
HTTP upload → очередь → фоновой обработчик → ready, владелец/status ACL,
MP4 Range 206 и отсутствие повторного кодирования при повторном PUT, отмена.

`test_account_video_cleanup_postgres.py` дополнительно проверяет additive
миграцию 0056 с сохранением старой ready-записи и очистку только новых
заброшенных загрузок/промежуточных исходников. Legacy и playback всех ссылочных
объявлений (включая проданные/удалённые) должны сохраняться. Локально PostgreSQL
не подключён; фактический результат этих двух тестов нужно читать в CI.

В CI после установки FFmpeg включён `RUN_ACCOUNT_VIDEO_BENCHMARK=1`. JSON
конкретного прогона сохраняется в `webapp/tests/evidence/account-video-processing/`.
Позднейшие результаты могут отличаться от приведённого локального замера.

## Воспроизведение

```powershell
$env:FFMPEG_BINARY = 'C:/absolute/path/ffmpeg.exe'
$env:FFPROBE_BINARY = 'C:/absolute/path/ffprobe.exe'
$env:RUN_ACCOUNT_VIDEO_BENCHMARK = '1'
# Запускать в backend, только с отдельными тестовыми настройками БД.
python -m pytest -q -s tests/test_account_video_processing.py
```

Для Linux CI достаточно доступных `ffmpeg` и `ffprobe` в PATH. Реальные
платежи, production-записи и Deploy при замерах не выполнялись.
