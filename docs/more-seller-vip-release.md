# «Ещё», VIP продавца, «О нас» и ручные выводы — 27 ноября 2026

## Реализовано

- «Ещё» — четыре кнопки по референсу. Реферальная программа перенесена на внутренний маршрут `referrals`, без изменения начислений, наград и ссылок. Нижняя навигация сохранена. Есть Back и защита от запоздавших ответов.
- `seller-vip` — серверные тарифы, стрелки/scroll-snap/клавиатура, подтверждение цены и источников, активная подписка, реальные счётчики и серверный срок. Клиент использует монотонное прошедшее время, а не часы телефона.
- 30 дней / 79 AF: 10 закреплений по 72 часа, максимум 15 активных машин / 10 аккаунтов. 90 дней / 249 AF: 45 закреплений по 72 часа и 23 по 24 часа, максимум 68 машин / 45 аккаунтов. Это итоговые активные лимиты, не пожизненное число публикаций.
- Покупка использует существующие wallet/ledger: сначала бонусы, затем purchased/earned. Ничего не начисляется продавцу или в выводимый баланс. `quote_fingerprint` связывает подтверждение с ценой, привилегиями и точными источниками оплаты. Изменение расчёта требует повторного согласия.
- Идемпотентность по пользователю/request UUID, уникальная активная подписка, серверные блокировки. Параллельные покупки не создают второе списание. При активном VIP новая покупка запрещена; автоматического продления нет.
- Бесплатное закрепление: выбор 72/24 часа перед публикацией или на существующем объявлении. Использование квоты и изменение `pinned_until` — одна транзакция, без AF. Ошибка не расходует квоту. После исчерпания остаётся прежнее платное закрепление. Само объявление после истечения подписки не удаляется; уже активированные закрепления сохраняют срок.
- Сервер проверяет лимиты и на обычной публикации, и на исполнении оплаченного черновика, и при административной повторной публикации. Для не-VIP прежние условия сохранены. После истечения VIP снова действуют стандартные правила платной публикации.
- SVG-галочка рядом с именем в карточке машины видна только во время VIP. Модальное объяснение прямо говорит, что VIP не подтверждает личность и не гарантирует безопасность сделки.
- Предупреждение за 24 часа и окончание VIP используют существующий персистентный Telegram outbox. Устаревшие уведомления после продления/отключения подавляются. Приложение открывать не требуется.
- Админка: список/фильтры/пагинация, источник оплаты, даты, остатки; выдача/продление/отключение требуют подтверждения и причины, проверяются сервером и пишут before/after в существующий audit. Support эти команды недоступны.
- VIP-приоритет фиксируется в заявке на вывод навсегда для этой заявки. Пометка/фильтр/сортировка и способ выплаты видны админу. Автоматической выплаты, изменения комиссии или обхода резерва нет.
- «Услуги ГГ / читы» показывает согласованное уведомление и реальную ссылку на канал, без создания нового магазина услуг.
- «О нас» — отдельная страница, история, планы, пять социальных ссылок и действующая поддержка для трёх тем. `/api/about` считает реальные аккаунты с положительным Telegram ID и только completed-сделки с датой завершения без отмены. Никаких исходных 3000/1500 и повторного прибавления базы.
- Инструкция по VIP добавлена к существующей справке; прежние инструкции покупки/продажи сохранены. Массовая рассылка не запускается.

## Данные и миграции

- `0057_seller_vip`: `seller_vip_plans`, `seller_vip_subscriptions`, `seller_vip_pin_usages`, `seller_vip_admin_commands`. Тарифы — в БД; подписка хранит снимок условий, финансовые источники/ledger-ссылку, даты, остатки и ссылки на уведомления. История не перезаписывается при изменении тарифа.
- `0058_withdrawal_methods_vip`: добавочные поля метода выплаты в quote и VIP-снимка/приоритета в заявке. Исторические заявки не получают выдуманный VIP и сохраняют прежний способ.
- Оба изменения добавочные; старые объявления, покупки, история и ключи аккаунтов не удаляются.
- `ACCOUNT_SALES_ENABLED` не изменён и не обходится VIP. Лимиты аккаунтов сохраняются, интерфейс показывает, что продажа временно недоступна.

## API

| Маршрут | Назначение |
|---|---|
| `GET /api/seller-vip` | Тарифы, активная подписка и server_now |
| `POST /api/seller-vip/quote` | Авторитетный расчёт источников и fingerprint |
| `POST /api/seller-vip/purchases` | Одна подтверждённая покупка, request_id + fingerprint |
| `GET /api/seller-vip/pins/{listing_id}/quote` | Доступные бесплатные закрепления |
| `POST /api/seller-vip/pins` | Атомарное закрепление без списания AF |
| `GET /api/admin/seller-vip` | Защищённый список подписок |
| `POST /api/admin/seller-vip/actions` | Выдать/продлить/отключить с audit |
| `GET /api/about` | Реальные агрегаты и явно настроенный аватар основателя |
| Существующие publication/seller-context/withdrawal API | VIP-лимиты, галочка, снимок приоритета и метод; прежние финансовые команды |

## Fragment: важный release gate

Код точного целочисленного ручного вывода подготовлен, **но выключен по умолчанию**: `FRAGMENT_WITHDRAWALS_ENABLED=false`. Официальные страницы `https://fragment.com/stars/buy` и `/about` при технической проверке возвращали 403; доступность 51/52/53 и границы диапазона не подтверждены. Нельзя обещать эти суммы или включать новую схему на основании сторонних публикаций.

До подтверждения сохраняется прежняя подарочная схема во всём прежнем диапазоне, включая действующий верхний предел. После осознанного включения и настройки проверенных min/max: по итоговому net <=50 — подарочные номиналы, >50 — точное целое количество Stars через ручной Fragment. Комиссия 30% применяется один раз; остаток остаётся в AF. Fragment API не вызывается. Подробный чек-лист: `withdrawal-fragment-release-gate.md`.

## Безопасная выкладка / rollback

1. Backup БД и проверка восстановления. Прогнать обе миграции на копии, проверить историю/балансы/объявления и CI gates. Не удалять шифроключи/медиа аккаунтов.
2. Review PR; не сливать и не запускать Railway автоматически. Перед разрешённым релизом проверить ACCOUNT_SALES_ENABLED=false и FRAGMENT_WITHDRAWALS_ENABLED=false. Не менять курс, комиссию и таймеры сделок.
3. После ручного разрешённого релиза: health, загрузка More/Market, SQL-counts, worker/outbox, ошибки API и ledger. Нет обязательной реальной транзакции для smoke-test.
4. При инциденте остановить новые VIP-покупки отключением тарифов (`seller_vip_plans.enabled=false`) через контролируемую административную DB-команду и зафиксировать причину; действующие подписки и закрепления не удалять. Активная карточка продолжает работать и без продаваемых тарифов.
5. При необходимости вернуть предыдущий image, **оставив добавочные таблицы, историю, ledger и VIP-снимки**. Не выполнять destructive downgrade после появления подписок. Возврат старого кода временно лишает новых UI-привилегий — оплаченные сроки/остатки должны быть сохранены и восстановлены/обработаны владельцем, не обнулены.
6. Fragment можно выключить отдельно; уже созданные заявки исполнять/отклонять существующей ручной командой, не менять их метод/суммы задним числом.
