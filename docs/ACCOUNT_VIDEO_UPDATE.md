# Видео аккаунтов — подключение существующего хранилища

## Что обнаружено

Предыдущий модуль `account_video.py` использовал исключительно S3. Существующий
Railway Volume приложения не использовался для видео аккаунтов. Read-only
проверка 16.11.2026 подтвердила диск 5 ГБ с mount `/app/backend/uploads`;
S3-бакетов и S3-настроек у рабочего сервиса нет. Новые платные ресурсы,
production-записи, платежи и Deploy в рамках этой задачи не создавались.

## Изменения

- Auto-detection существующего Railway mount, приватная `.account-videos`,
  запрет её выдачи через старый публичный `/uploads`.
- Потоковый авторизованный PUT: проверка владельца, размера и контейнера;
  временный файл, fsync, immutable hash-key, короткая блокировка записи.
  Повтор одинакового PUT безопасен; подмена подтверждённого файла запрещена.
- Native HTTP Range/206/416 без долгого удержания подключения к БД. Одночасовая
  зашифрованная ссылка ограничена видео/пользователем; ACL проверяется заново.
  Cookies не требуются. Uvicorn access-log скрывает query этой ссылки.
- Существующие S3-видео сохраняют свой provider. Миграция БД не требуется.
- Медиатека без принудительного открытия камеры: MP4/MOV/WebM, до серверного
  лимита. Реальный формат/кодек должен поддерживаться устройством; для общей
  совместимости рекомендован MP4 H.264. Транскодирование не добавлено.
- Плеер в карточке: просмотр по нажатию, пауза, перемотка, скорости
  0.5/1/1.25/1.5/2/3/5×. Ошибка/повторная загрузка, сохранение позиции при
  обновлении карточки, пауза при уходе с экрана, защита от устаревшего ответа.
- В данных аккаунта и подтверждении получения: сверка описания/видео,
  обязательная смена привязанной почты, пароля и восстановления до подтверждения;
  предупреждение, что продавец может попытаться вернуть доступ. Это не гарантия
  невозможности восстановления аккаунта продавцом.
- Checkbox, существующий cooldown, escrow, выплата, стоимость и VIP не менялись.

## Проверка и ограничения

Локально проверены реальный WebM через HTTP/файловую систему и production-плеер
в Chromium на 320/390/430 px: decoding, Range, seek, play/pause, 2×/5×,
обновление без сброса, отсутствие cookies, новый текст и отмена подтверждения.
SQLite/HTTP тесты проверяют права, повреждённые/просроченные ссылки, закрытый
публичный путь, неверный контейнер/размер, идемпотентность и redaction логов.
В CI добавлены signed Telegram + isolated PostgreSQL: CP1/CP2, восемь
одновременных загрузок, доступ покупателя, скрытие объявления, restart и
реальный browser playback. Результат конкретного запуска — в checks PR.

Физические iPhone/Android внутри Telegram не подключены. Пробный Windows
WebKit не прошёл decoding используемого WebM; это не заменяет проверку Safari
и реальных файлов MP4/MOV на устройствах. Не заявляем полную проверку iOS.

У production пока нет `ACCOUNT_SALES_ENABLED`, `ACCOUNT_SECRET_KEYS`,
`ACCOUNT_SECRET_ACTIVE_KEY`. Общий раздел аккаунтов остаётся закрытым прежним
release gate; не включать его без защищённой настройки ключей и решения
владельца. Хранилище в новой версии дополнительных ключей не требует.
Лимит диска конечный: мониторить свободное место, backups и один app replica.
Rollback/безопасное обслуживание описаны в `ACCOUNT_SALES_RELEASE.md`.
